# 1. Kontext

Im Rahmen der Projektdokumentation wurde festgelegt, dass Informationen nicht mehrfach in unterschiedlichen Dokumenten gepflegt werden. Redundante Inhalte führen langfristig zu Inkonsistenzen und erhöhen den Wartungsaufwand.

---

# 2. Entscheidung

Für das Projekt **s-bac.de** gilt das Prinzip **Single Source of Truth (SSOT)**.

Jede fachliche oder technische Information besitzt genau eine maßgebliche Quelle. Andere Dokumente verweisen auf diese Quelle, anstatt Inhalte zu duplizieren.

---

# 3. Begründung

Das SSOT-Prinzip bietet folgende Vorteile:

- Vermeidung widersprüchlicher Informationen
- Geringerer Pflegeaufwand
- Einheitliche Terminologie
- Nachvollziehbare Änderungen
- Verbesserte Wartbarkeit der Dokumentation

---

# 4. Betrachtete Alternativen

## Mehrfache Pflege identischer Informationen

**Vorteile**

- Informationen stehen unmittelbar im jeweiligen Dokument zur Verfügung.

**Nachteile**

- Hohe Gefahr inkonsistenter Inhalte
- Erhöhter Pflegeaufwand
- Fehleranfälligkeit bei Änderungen

Diese Alternative wurde verworfen.

---

# 5. Auswirkungen

Für alle Projektdokumente gilt:

- Informationen werden nur an einer Stelle gepflegt.
- Dokumente verweisen aufeinander, anstatt Inhalte zu kopieren.
- Änderungen erfolgen ausschließlich an der maßgeblichen Quelle.
