# 1. Kontext

Mit zunehmendem Umfang der Projektdokumentation steigt die Bedeutung einer klaren Struktur. Strategische, fachliche und technische Informationen müssen dauerhaft auffindbar, konsistent und nachvollziehbar organisiert werden.

---

# 2. Entscheidung

Für das Projekt **s-bac.de** wird ein zentrales Dokumentationsportal im Verzeichnis `docs/` verwendet.

Alle Projektdokumente werden dort nach einem einheitlichen Dokumentationsstandard gepflegt. README, INDEX, Glossar, ADRs und die Hauptdokumente bilden gemeinsam die verbindliche Wissensbasis des Projekts.

---

# 3. Begründung

Das Dokumentationsportal bietet folgende Vorteile:

- Einheitlicher Einstiegspunkt für alle Projektbeteiligten
- Klare Struktur und Navigation
- Zentrale Pflege aller Projektdokumente
- Bessere Nachvollziehbarkeit von Zusammenhängen
- Langfristig wartbare Dokumentation

---

# 4. Betrachtete Alternativen

## Verteilte Einzeldateien ohne zentrale Struktur

**Vorteile**

- Geringer initialer Aufwand

**Nachteile**

- Erschwerte Navigation
- Höheres Risiko redundanter Inhalte
- Schlechtere Wartbarkeit

Diese Alternative wurde verworfen.

---

# 5. Auswirkungen

Für das Projekt gilt:

- Neue Dokumente werden in den INDEX aufgenommen.
- Dokumente verweisen aufeinander, anstatt Inhalte zu duplizieren.
- README und INDEX dienen als zentrale Einstiegspunkte.
- Architekturentscheidungen werden zusätzlich als ADR dokumentiert.
