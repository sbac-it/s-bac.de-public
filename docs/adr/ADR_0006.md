# 1. Kontext

Die Website s-bac.de soll langfristig erweiterbar, wartbar und konsistent bleiben. Wiederkehrende Seitenelemente wie Hero-Bereiche, Karten, Kontaktabschnitte oder Call-to-Action-Elemente sollen nicht mehrfach individuell umgesetzt werden.

---

# 2. Entscheidung

Die Website wird nach dem Prinzip der komponentenorientierten Entwicklung aufgebaut.

Wiederverwendbare UI-Komponenten bilden die Grundlage für Seitenaufbau und Weiterentwicklung. Neue Inhalte werden bevorzugt durch die Kombination bestehender Komponenten erstellt.

---

# 3. Begründung

Diese Entscheidung bietet folgende Vorteile:

- Einheitliches Erscheinungsbild
- Wiederverwendbarer Code
- Geringerer Wartungsaufwand
- Schnellere Entwicklung neuer Seiten
- Einfachere Qualitätssicherung
- Höhere Konsistenz zwischen Design und Implementierung

---

# 4. Betrachtete Alternativen

## Individuelle Entwicklung jeder Seite

**Vorteile**

- Maximale Gestaltungsfreiheit pro Seite

**Nachteile**

- Redundanter Code
- Inkonsistentes Erscheinungsbild
- Höherer Pflege- und Testaufwand

Diese Alternative wurde verworfen.

---

# 5. Auswirkungen

- Neue Komponenten werden im Komponentenkatalog dokumentiert.
- Bestehende Komponenten werden bevorzugt wiederverwendet.
- Änderungen an einer Komponente werden hinsichtlich ihrer Auswirkungen auf alle Verwendungen geprüft.
