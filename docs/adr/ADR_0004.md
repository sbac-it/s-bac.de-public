# 1. Kontext

Die Projektdokumentation und der Quellcode entwickeln sich parallel weiter. Änderungen müssen nachvollziehbar, reproduzierbar und dauerhaft dokumentiert werden.

---

# 2. Entscheidung

Für das Projekt **s-bac.de** wird Git als Versionsverwaltung und GitHub als zentrales Remote-Repository eingesetzt.

Sämtliche Änderungen an Dokumentation, Quellcode und Konfiguration werden versioniert und über aussagekräftige Commits dokumentiert.

---

# 3. Begründung

Die Entscheidung bietet folgende Vorteile:

- Vollständige Nachvollziehbarkeit aller Änderungen
- Rückverfolgbarkeit von Architekturentscheidungen
- Sichere Zusammenarbeit
- Einfache Wiederherstellung früherer Stände
- Saubere Release- und Entwicklungsprozesse

---

# 4. Betrachtete Alternativen

## Lokale Dateiverwaltung ohne Versionskontrolle

**Vorteile**

- Keine Einarbeitung in Git erforderlich

**Nachteile**

- Keine Historie
- Höheres Risiko von Datenverlust
- Keine strukturierte Zusammenarbeit

Diese Alternative wurde verworfen.

---

# 5. Auswirkungen

- Alle Änderungen werden versioniert.
- Commits beschreiben den fachlichen Zweck der Änderung.
- Dokumentation und Quellcode werden gemeinsam gepflegt.
- GitHub dient als zentrale Referenz für den Projektstand.
